# Sonik 7 Cloud IP — прошивка без ночного включения экрана

Патч штатной прошивки **Sonik_7_Cloud v3.0.1.3** для видеодомофона Sonik 7 Cloud IP.
Устраняет ежедневное включение подсветки экрана примерно в 03:30–03:35 (на пару секунд
показывался главный экран).

Номер версии в системе не меняется — остаётся **3.0.1.3**. Всё, кроме одного байта
в приложении, идентично официальной прошивке.

---

## Проблема

Каждую ночь около 03:30 приложение `doorbell` выполняло служебный «тихий» перезапуск
(в логе — `Silense reboot`). Устройство при этом не перезагружалось, но на ~5 секунд
включался экран с главным экраном, после чего снова уходил в режим ожидания.

Причина в коде — вызов в `app_standby_proc`:

```
IsRebootTime(86400, 3, 30)   // «раз в сутки в 03:30»
```

Вызов ровно один на всю прошивку, других триггеров нет.

## Решение

В `/usr/bin/doorbell` изменён **один байт**:

| | Инструкция | Байты |
|---|---|---|
| Было | `mov.w r1, #3` (час 3) | `4F F0 03 01` |
| Стало | `mov.w r1, #255` | `4F F0 FF 01` |

Теперь проверка сводится к `IsTime(255, 30)`:

* целевая минута суток = `255 * 60 + 30 = 15330`;
* в сутках максимум 1439 минут;
* условие `now >= 15330 && now < 15360` не выполняется **никогда**.

То есть перезапуск не «перенесён», а полностью отключён.

**Смещения:**

| Что | Значение |
|---|---|
| Виртуальный адрес (vaddr) | `0x6CC86` (инструкция с байтом часа — `0x6CC8E`) |
| Файловое смещение в `doorbell` | `0x64C90` |
| Блок squashfs | №3, смещение `0x4C90` в блоке |
| Файловое смещение блока в образе | `0x4C3B08` |

Правка сделана прямо внутри сжатого XZ-блока squashfs. Блок пересжат ровно до исходных
38 652 байт, поэтому размеры, смещения разделов и CRC заголовка образа не изменились.

## Установка

Подготовка (для любого способа):

1. Карта microSD: **FAT32**, разметка MBR, лучше пустая (**1–128 ГБ**).
2. Скопировать `update.ius` в **корень** карты. Имя менять нельзя — ровно `update.ius`.

### Вариант 1 — автоматически с SD-карты (переход с другой версии прошивки)

Работает, когда прошивается **другая** версия (обновление/понижение).

1. Обесточить домофон, вставить карту, подать питание.
2. Устройство само запустит запись. **Не отключать питание и не вынимать карту.**
3. Дождаться сообщения:
   `BURN SUCCESS, Remove ius card to enter the new system.`
4. Вынуть карту. Устройство загрузится с новой прошивкой.

### Вариант 2 — через меню видеодомофона (прошивка той же версии)

Если прошивается **та же версия**, что уже установлена (в нашем случае 3.0.1.3),
автоматический прожиг с карты при загрузке не запускается. В этом случае:

1. Вставить карту с `update.ius` в домофон.
2. Открыть меню устройства → пункт **«Обновление»** (в этом же разделе
   показывается «Версия прошивки»; точное название и расположение пункта
   могут немного отличаться в зависимости от версии интерфейса).
3. Запустить обновление и дождаться завершения — **не отключать питание**.
4. После сообщения об успехе вынуть карту, устройство перезагрузится.

Если обновление не стартует: проверить, что файл лежит именно в корне и назван
`update.ius`, попробовать другую карту (карты с exFAT U-Boot не читает).

## Как проверить

* Ближайшие ночи около 03:30 экран включаться не должен.
* В логе не должно появляться `Silense reboot`.
* Остальное (звонки, приложение, сеть, запись) работает как раньше.

Тест «вручную»: выставить время 03:30, погасить экран и не трогать устройство
2–3 минуты. На оригинальной прошивке будет вспышка, на патченной — тишина.
Условие в коде дополнительно требует uptime ≥ 24 часов (монотонные часы),
поэтому на устройстве, которое только что перезагружалось, тест может не сработать
даже без патча.

## Важно

* Образ содержит не только rootfs, но и U-Boot, ядро и ramdisk — прошивка идёт
  полной перезаписью разделов. **Пропадание питания в момент записи может превратить
  устройство в «кирпич».**
* Это неофициальная прошивка: гарантия и поддержка производителя после неё могут
  не действовать.
* Отключён ежедневный профилактический перезапуск приложения. Если со временем
  появятся подтормаживания — достаточно перезагрузить устройство вручную.

## Откат

Прошить оригинальный `update.ius` (SHA256
`8b4487ff60a381a249b4714869f7afed41d2ca2f618e2252d8b99f440c65c0c3`) тем же способом —
ночное включение вернётся.

## Технические детали и проверки

* Контейнер `+ius`: 7 записей (U-Boot `+isi`, ramdisk, kernel, rootfs squashfs XZ,
  resource squashfs). Размер файла не изменился.
* CRC заголовка `+ius` (поле `0x18..0x1B`, считается по первым `0x200` байтам):
  `0x8A0D2350` — совпадает с оригиналом.
* Проверка целостности архива 7-Zip проходит, `doorbell` извлекается и отличается
  от оригинала ровно одним байтом.
* Сжатый блок XZ (LZMA2, dict 128 КиБ = размер блока) декомпрессируется в корректные
  131 072 байта с патчем.
* Все отличия от оригинального образа лежат только внутри этого блока.
* В прошивке нет проверки версии/хэшей образа при обновлении (`ius_check_image` —
  пустая заглушка).

### Альтернатива: перенести перезапуск на день

Если хочется сохранить ежедневный перезапуск, но сделать его незаметным, тот же байт
`0x64C90` меняется на `0x0D` (час 13) → `mov.w r1, #13`.
